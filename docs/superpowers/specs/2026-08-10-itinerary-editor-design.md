# 意大利 / 东京行程编辑器与内容增强设计

日期：2026-08-10  
状态：已确认视觉与功能方向，待实现

## 目标

在不合并意大利与东京独立入口的前提下，为两份攻略共用一套行程编辑组件：现有 49 条记录均展示对应图片；著名景点详情增加历史文化和注意事项；用户可以在手机或桌面端调整顺序、删除和新增行程。所有编辑继续按目的地保存在浏览器本地，不引入账号或云同步。

## 内容与视觉

- 现有 27 条意大利记录和 22 条东京记录各配一张本地 WebP 图片；景点使用 Wikimedia Commons 等开放授权实景图，机场与交通节点使用对应设施或交通场景图。
- 图片统一裁切为横向 `3:2`，放在详情顶部；折叠状态保留一条窄幅图像预览，避免时间轴变成纯文字表格。
- 为数据增加 `nameEn`、`nameLocal`、`image`、`imageAlt`、`culture`、`tips` 字段。`culture` 用于历史、建筑、宗教或艺术背景；`tips` 用于预约、着装、开放规则、安全和交通注意事项。
- 每条景点、地点和交通节点都显示三语名称：中文作为主标题，English 作为第一行对照，当地语作为第二行对照；意大利行程的当地语为意大利语，东京行程为日语。英文名与当地语相同时仍保留两个带语言标签的字段，保证信息结构一致。
- 交通节点没有历史文化时显示“行程背景”，不强行编造文化内容。
- 图片来源与许可记录在 `assets/places/credits.json`，页面底部提供“图片来源”入口。

## 编辑交互

### 排序

- 每条记录增加可识别的拖动把手，整张卡在拖动中产生轻微抬升和路线节点位移动画。
- 桌面端支持 HTML Drag and Drop；触屏端使用 Pointer Events，纵向移动越过相邻记录中心点时实时交换位置。
- 键盘用户可聚焦把手，用 `Alt + ↑/↓` 调整顺序，并收到屏幕阅读器状态提示。
- 排序完成后自动重算开始时间：下一条开始时间 = 上一条开始时间 + 上一条游览时长 + 两站之间的交通时长。
- 数据增加结构化 `travelMinutes` 与 `timeMode`。`timeMode` 为 `fixed` 或 `flexible`；航班、火车、轮渡和分时预约默认是固定时间锚点，普通景点默认可调整。
- 自动重算只推进可调整记录；遇到下一个固定时间锚点时停止并检查是否冲突。空间不足时保留固定时间并显示“行程时间冲突”，不悄悄覆盖已确认预约。

### 时间编辑

- 每条记录的开始时间、游览时长和下一段交通时长均可在详情中修改；开始时间使用移动端友好的时间输入控件。
- 修改任意记录的开始时间后，该记录成为当前计算起点，并连锁更新后续可调整记录，直到下一个固定时间锚点。
- 用户可以切换“固定时间 / 自动调整”。解锁固定记录前给出预约提示；重新锁定后以手动输入时间作为新锚点。
- 每次自动重算后显示简短摘要，例如“已更新后续 3 条时间”；排序、时间修改和锁定状态均按目的地持久化。

### 删除

- 触屏左滑超过阈值后露出红色“删除”按钮；桌面和键盘用户可通过卡片操作区直接访问同一按钮。
- 左滑本身不立即删除，点击删除后记录进入可撤销状态；Toast 在 6 秒内提供“撤销”。这样避免误触导致不可恢复的数据丢失。
- 删除和撤销只影响当前目的地与当前日期。

### 新增与联网补全

- 每个日期的时间轴底部放置“添加一条行程”，打开内联编辑面板，默认归属当前日期。
- 用户输入地点关键词后点击“联网搜索”，前端并行调用中文、英文及目的地当地语言的维基百科公开 API，获取候选标题、摘要、资料页和缩略图；用户选择一个结果后自动填充三语名称、文化简介、图片和资料链接。
- 搜索结果无法可靠匹配三语页面时保留空字段并提示用户确认，不用机器猜测或把中文名称复制成当地语。
- 时间、分类、时长、费用、地址、下一段交通仍由用户确认；Google Maps 搜索链接由名称与地址本地生成。
- 搜索结果不把维基百科资料页冒充景点官网，数据中新增 `reference` 链接并在界面标为“资料来源”。
- 无网络、无结果或 API 失败时显示明确提示，保留手动填写与保存能力。

## 数据与模块边界

### 基础旅行数据

`data/trips.json` 继续作为只读基础内容。现有地点增加三语名称、图片与结构化介绍字段，地图、官网和预约链接保持原有合同。

### 本地编辑状态

状态版本升级为 2，并增加：

```text
itinerary.customPlaces[placeId] = Place
itinerary.deletedPlaceIds[placeId] = true
itinerary.dayOrder[date] = [placeId, ...]
itinerary.placeOverrides[placeId] = { time, durationMinutes, travelMinutes, timeMode }
```

渲染时先合并基础地点与自定义地点，再过滤已删除项，最后应用 `dayOrder`。基础 JSON 后续增加新景点时，新记录会自动追加，不会被旧的本地快照遮蔽。

### 代码模块

- `src/core.mjs`：状态迁移、数据校验和地图链接。
- `src/itinerary.mjs`：合并、排序、时间重算、冲突检测、新增、删除与撤销的纯函数。
- `src/search.mjs`：维基百科查询、结果规范化、超时与错误映射。
- `src/view.mjs`：图片、文化/注意事项、滑动轨道和新增面板的 HTML。
- `src/gestures.mjs`：拖动与左滑手势，只输出意图事件，不直接写存储。
- `src/app.mjs`：协调事件、状态持久化、搜索请求和重新渲染。

## 离线与安全

- 49 张现有图片加入 Service Worker 应用缓存，保证首次在线安装后离线可查看。
- 用户联网搜索得到的远程图片在成功加载后尝试加入运行时缓存；未缓存或加载失败时展示本地地图纹理占位图。
- 搜索请求使用 `encodeURIComponent`，所有渲染内容继续经 HTML 转义；自定义外链只接受 `https://`。
- 删除提供撤销，不引入跨目的地批量删除。

## 测试与验收

- 单元测试覆盖状态 v1→v2 迁移、基础/自定义地点合并、固定/弹性时间重算、冲突检测、排序、删除、撤销、搜索结果规范化和无效链接处理。
- 数据测试要求 49 条现有记录具备中文、英文、当地语名称、图片、替代文本、交通时长、时间模式与注意事项；著名景点具备非空文化介绍；图片文件与授权清单可对应。
- 浏览器测试分别在意大利和东京验证：桌面拖动、触屏重排、自动更新时间、手动改时与锁定、时间冲突提示、左滑露出删除、删除撤销、联网搜索填充、手动新增、刷新后持久化、两地状态隔离。
- 在 390×844、768×1024、1440×900 检查无水平溢出，所有按钮至少 44px；在离线模式检查正文、现有图片与编辑状态可访问。
- 截图 QA 覆盖两地手机和桌面视图，重点检查三语名称的层级、图片裁切、展开详情、拖动态、删除轨道与新增面板。

## 非目标

- 不提供账号、云同步、多人协作或服务端数据库。
- 不自动修改基础 JSON；用户新增与调整只存在本地浏览器。
- 不把维基百科摘要当作最终权威开放时间；开放规则仍以景点官网和已保存的注意事项为准。
